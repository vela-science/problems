# Vela Web v0.440.0

Vela Web 0.440.0 adds the frontier-edges projection: a derived table of typed
relationships between retained records, each carrying the exact basis class
that justifies stating it.

- `projection.frontier_edges` is a new additive table. Every row names two
  retained objects, one relation, one of five basis classes
  (`source_asserted`, `mechanically_verified`, `authority_decided`,
  `exact_derivation`, `heuristic_advisory`), and a `basis_ref` naming the
  retained record the basis rests on. Heuristic groupings state in
  `nonclaims` what they do not establish. The table opens the immutable
  migration ledger as `0001_frontier_edges.sql`.
- The release manifest gains a `frontier_projection` block — schema, edge
  count, and per-basis counts — hashed under `release_root` like everything
  else the manifest states. Manifests from earlier releases stay readable
  without it.
- Two SELECT-only readers serve the edges: `problemFrontier` returns one
  bounded window grouped by basis, and `problemFrontierTimeline` orders the
  exact state-change edges of one Problem into anchored t-states. Gaps —
  occurrences without an accepted Result, unresolved equivalence, a check's
  own declared limits — are derived from the window in the reader and never
  stored.
- The Problem History tool gains "How the frontier moved": ordered temporal
  states with accepted and removed Results, an evidence flow from Submission
  to Result standing, and a labeled basis chip on every stated relationship.
  The section exists only for a Problem whose reviewed entity has verified
  state-change edges; every other Problem's History renders unchanged.

The frontier projection is a derived read model. It introduces no new
protocol object, computes no importance score, and its edges only restate
records the projection already retains; an edge never changes Standing. The
scientific projection and hosted Activity planes remain non-authoritative.
Only an authorized Vela Decision changes Standing.
