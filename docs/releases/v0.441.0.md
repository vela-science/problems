# Vela Web v0.441.0

Vela Web 0.441.0 adds the first read-only external-registry source and removes
operator machinery the executed journey exposed.

- The Palomar registry joins the declared sources through a read-only adapter.
  The retained record is `PALOMAR-2026-08-19-000002` version 1, the Lean 4
  ZFC-independence resolution of Erdős 501, held byte-exact under a
  consumer-computed root with both evidence-report digests re-verified.
  Palomar's registered status is external standing: every binding this
  adapter produces is a reference with no local standing effect, and the
  frontier states nothing stronger than the source's own assertion. Ten
  semantic-loss disclosures ride in the declaration and observation data.
- The governed release now assembles its own operator environment: it reads
  the local reader URLs (with their quoting), derives the writer and migrator
  URLs through neonctl when absent, and fails closed naming the missing
  credential. A hand-assembled environment broke one release run; this
  removes the hand assembly.
- Seven hand-copied Vela pin literals are gone: the binary acquisition script
  and the Core integration inspector now read the one release record. One
  sync script vendors the upstream schemas for both packages.
- Dependency updates: the web-dependencies group (Next 16.3.1 line) and
  jest-dom 7, both qualified locally; the postcss override moves in lockstep.
  The group's shadcn bump is held back at the design system's declared exact
  4.16.1 pin; moving that pin is its own visually qualified change. A dead
  `./editorial` export entry is removed.

No table, manifest, or reader contract changed shape; the new source flows
through the existing declaration, observation, and native-record surfaces.
Only an authorized Vela Decision changes Standing.
