# Vela Web v0.442.1

Vela Web 0.442.1 gives the activity plane one table inventory instead of three.

- The live proof asserted the activity table count as a literal, the schema
  check asserted the same inventory by name, and a governance test asserted the
  live proof's literal as source text. Adding `pilot_telemetry` satisfied the
  first list and contradicted the other two, which nothing without a database
  could see, so the 0.442.0 release stopped at activity qualification after its
  projection had already been activated. Production was returned to its prior
  matched projection and deployment while this was fixed.
- The inventory now lives once, in `packages/activity-data/scripts/expected-tables.mjs`.
  The schema check and the live proof both import it, and the governance test
  asserts that binding rather than the number it produces.

This is the second additive table to break a count pinned in a check that only
runs during a release. The first was the projection writer's statement count,
whose database-free half now runs in every ordinary gate.

Only an authorized Vela Decision changes Standing.
