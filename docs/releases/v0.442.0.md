# Vela Web v0.442.0

Vela Web 0.442.0 corrects what the product claims, makes the frontier movement
readable, and opens one bounded pilot-telemetry endpoint.

- A frozen comparison against FAR and a public problem registry found FAR
  stronger at literature-scale discovery and effort allocation, and found
  separated attempt, machine-check, formal-check, and status surfaces already
  present in a competing product. Copy on the landing page, the About boundary
  panel, and PRODUCT.md now says so and states the narrower boundary the
  evidence supports: exact source custody, independently scoped Checks, an
  attributed Repository Decision with its Event and Standing, linked correction
  with replay, and reconstruction from Git alone. PRODUCT.md carries the rule so
  the copy does not drift back.
- The frontier movement section states itself in reader words. Result
  references carry the same short headline the Overview derives rather than the
  full retained assertion, which appeared seven times on one Problem's history.
  The correction comparison now expresses its two live cases: an unchanged
  statement whose relations were revised, and a predecessor this release does
  not retain. Gap sentences lead with their subject and keep exact identifiers
  under the existing disclosure. A basis of exact derivation reads as derived
  from records. An agent performer is named as an AI agent at first layer.
- The per-Problem promotions of the research map are removed. The route, its
  About entry, and the command palette remain. Every Problem page tab already
  enumerates what the map could show for one Problem.
- `activity.pilot_telemetry` accepts nine content-free stage signals from an
  opted-in Workbench install: stage name, timestamp, install identifier,
  per-record identifier, and elapsed duration. It stores no content, identity,
  or account reference, and no column could hold one. Ingestion is bounded by a
  per-install budget and a global hourly ceiling, refuses any unexpected field,
  requires a JSON content type, and never echoes a received value in a refusal.
  The threat model records the growth and pseudonymity residuals rather than
  implying they are absent.

The pilot telemetry migration is forward-only under the exact-inventory check:
after it applies, an older build refuses the extra table. Retention runs on the
write path, so the store must be dropped when the pilot ends for the published
90-day claim to stay true.

Only an authorized Vela Decision changes Standing.
